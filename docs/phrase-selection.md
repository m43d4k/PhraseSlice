# 録音のフレーズ選定と語尾調整

録音のフレーズ選定・語尾調整を依頼されたときに適用する。パスはすべてリポジトリ直下を基準とする。

## 親エージェントの手順

必要な選定品質を保ちながら、親子合計のトークン消費を抑えることを目的とする。

1. 入力パスが省略されたら、`rg --files --hidden --no-ignore dist -g transcript.json` で候補を探す。親フォルダを `dist/` からの相対名で番号付きで示し、どの録音を処理するかユーザーに尋ねる。候補が1件でも選択を待つ。候補がなければ `uv run transcribe.py` を案内する。
2. 録音が決まったら、[`.codex/agents/phrase_selector.toml`](../.codex/agents/phrase_selector.toml) で定義した `phrase_selector` 1体に選定を委譲する。モデルと推論レベルは同ファイルの `model` と `model_reasoning_effort` に従う。名前付きエージェントを指定できない実行環境では、同ファイルを読み、モデル・推論レベル・`developer_instructions` を明示して起動する。設定の欠落や指定モデルの利用不可で起動できなければ、原因を報告して停止する。
3. 子エージェントには会話履歴を引き継がず（`fork_turns="none"` を指定できる場合は指定する）、リポジトリの絶対パス、選ばれた `transcript.json` と同じフォルダの保存先 `phrase-ends.json` の絶対パス、上記TOMLの指示だけを渡す。
4. 完了を待ち、保存された配列のスキーマ適合、全IDの存在、厳密な昇順、最終単語IDとの一致を `uv` で動かすローカル処理で検証する。親は選定を重複実行しない。
5. 使用モデル、推論レベル、保存先と検証結果を簡潔に報告する。

## 子エージェントの手順

1. 親が指定した `transcript.json` を読み、発話の意味と休止を手掛かりに、文字起こしに存在する単語IDから各フレーズの末尾を選ぶ。
2. 同じフォルダの指定された `phrase-ends.json` に、[出力スキーマ](../schemas/phrase-ends.v1.schema.json) に従って末尾IDの配列だけを書く。IDは厳密な昇順で、末尾は入力の最終単語IDに一致させる。
3. 保存先とフレーズ数を簡潔に返す。

選定はこの子エージェントが直接担当する。追加の子エージェントは起動しない。

## 語尾の調整

選定済みのIDを再利用し、時刻とフレーム位置はローカル処理で決める。再調整のたびにモデルへ選定を依頼しない。

## モデルの採用と更新

- モデル名と推論レベルの指定は `.codex/agents/phrase_selector.toml` に集約する。通常のフレーズ選定では設定済みの組み合わせを使う。
- モデル更新の依頼、提供終了の告知、利用不可の判明を見直しの契機とする。見直す際は現在日時を確認し、公式情報と実行環境で利用可能なモデル・推論レベルを確認する。
- 軽量モデルと必要最小限の推論レベルから候補を検討する。同じ文字起こしと同じ選定指示で比較し、発話の意味と休止に沿う区切りになっているかを確認する。IDの形式検証だけで選定品質を判定しない。
- 品質を満たした候補のうち、親子合計の入力・出力トークン数が実測で少ない組み合わせを採用する。取得可能なら推論トークン数も内訳として確認する。モデル単価や軽量という分類だけでトークン数の削減を判断しない。比較はモデル見直し時に行う。
- 実測できない場合は消費削減を確認済みとして扱わず、比較できなかった項目を報告する。未検証の初期設定は暫定候補と明記する。
- 更新時は上記TOMLのモデル・推論レベルとコメントを変更し、比較した録音、品質の確認結果、取得できた消費量、採用理由をコメントに残す。
